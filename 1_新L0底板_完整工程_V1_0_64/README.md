## 恢复采集任务的错峰规则判断（2026-10-22）

此前 `lora_self_report_due()` 在存在采集任务时直接放行，只等读取窗口结束，因此跳过原有周期错峰及邻居令牌判断。本次仅修改 `User/LoraPro.c`：采集完成只创建待上传任务，发送仍需通过原有 `RfTick` 周期（含首次台号相位）或邻居令牌条件；`Ble_flag_data` 的启动补发不能绕过待上传任务的判断。失败轮次仍独立退避30秒，并按任务代号保留重试资格，新采集不能继承旧轮次的放行资格。仅在实际选中本机任务时消费重试状态，转发先行不消耗它。

采集周期和计划、台号相位方向、原令牌生命周期、协议、射频驱动、早醒处理及屏幕固件未改变。若采集完成时原有周期或令牌条件已经满足，仍允许发送；本次恢复规则检查，不增加每轮采集后的固定延迟，也不据此声称实际多机碰撞已经消除。
