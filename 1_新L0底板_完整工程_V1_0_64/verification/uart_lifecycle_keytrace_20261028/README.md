## UART修改

两处关闭入口使用`UART1_DeInitSafe()`，先禁止USART1 IRQ，在时钟有效时清旧中断、错误、RX字节及pending，再调用HAL DeInit，由其内部关闭外设时钟。初始化时IRQ保持关闭，实际安装接收处理函数、进入BUSY_RX后才开放IRQ。

RXNE中断触发但RxISR为空时保存现场并关闭该接收中断，交给主循环重新武装，不在中断打印或喂狗。正常逐字节接收和USART2初始化保持。

独立64字节`UNINIT`检查点在有效IWDG/软件复位后由`[U1PRE]`输出，含stage、原UART寄存器、接收处理指针、IPSR及IRQ计数。原子提交、校验及复位原因检查防止将损坏或上电RAM当作旧现场。它是最后检查点，不是故障历史，也不自动证明UART导致重启。掉电不承诺保留；HardFault记录不含故障PC/LR。详见`UART_IMPLEMENTATION.md`。

Keil使用新`MDK-ARM/uart_fault_noinit.sct`，UART区为`0x20001FC0..0x20001FFF`。startup原1024字节栈和1536字节堆保留。CubeMX重新生成或更换链接配置时须保留这一布局及UART业务扩展。

## 日志修改

普通32槽、RF6槽容量保持。重复自发发送/退出/超时及CAD接收结束按采集阶段压缩；原始累计计数仍逐次增加。首次自发超时、自愈、业务成功、射频状态兜底优先保存。普通队列预留8个关键槽，满载关键事件会替换非关键记录；全关键超载仍可能丢失。

RF最多4份普通快照及最近的恢复前后快照，当前任务第一次确认超时受保护。恢复保留pending seq，但清重复掩码，因此恢复后同seq的首次接收/确认超时仍能记录。容量不足时替换普通快照或旧恢复快照，明确计入rlost；新任务可以替换旧任务证据。

- `[LS] compact/rcompact`：普通/RF重复压缩累计。
- `[LS] lost/rlost`：容量造成的拒入或替换累计。压缩与容量损失分开。
- `[LC]`：ready、replace、selftx、fwdtx、txexit、rx、stmo、ftmo、ffail、sok、fok、hbegin、hend、watch的本启动周期原始累计，包含已压缩及丢失的事件。
- `[LK]/[RF] rt`为捕获时间；输出可延期，队列并非跨复位保存。不能把PC打印时间当空口发生时间。
- 保留原清醒窗口和收发空闲输出门控，每次Service最多一行；不为日志增加唤醒。没有新增空口序号，DONE仍沿用原协议确认判据。

## 复测

本轮未烧录。仅在身份及型号明确的2/5/35号同型底板进行后续授权测试；1/3号旧产品不使用本镜像。确认LK3和600秒配置，保持原接线、拓扑和参数同步记录两端串口与分站实际新数据。至少跨3个采集周期，并继续覆盖此前跨夜故障时长。

检查重复息屏/唤醒和周期采集是否持续完成，是否仍有IWDG；若重启，保留启动最前面的U1PRE与复位原因。失败时核对LC超时/恢复/成功增量和RF首故障、恢复后快照，不能仅凭HEAL_END或DONE当作指定新采样到站成功。测35号需增加其自身连续串口。

尚未验证：真实板卡的IRQ/寄存器清理效果、跨IWDG的RAM现场保留、长期采集与转发连续性、功耗、测量准确性和栈峰值。
