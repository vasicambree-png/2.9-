# 2.9 寸屏：底板启动图与屏幕 S2 复位入口

当前文件夹仅用于 2.9 寸 ST7305，物理 168×384，R3 逻辑画面 384×168。误加的 ST7306 试验入口和花纹图已撤回，原有未调用的备用函数保留。4.2 寸应在用户后续独立复制的工程中开发。

## 当前行为

| 触发来源 | 显示顺序 |
|---|---|
| 底板正常复位启动，发送原有 rank=5，再发送主页 | 初始化图，再显示最新主页 |
| 屏幕普通上电后的首次有效页面 | 初始化图，再显示最新页面；只有供电/CMD03/msg0不触发 |
| 已有页面熄屏后，K1、K2、K3单键产生可识别的导航变化 | 初始化图，再显示按键对应页面 |
| 亮屏期间正常导航 | 直接更新页面，不重复初始化图 |
| 屏幕 S2 外部硬件复位，RST 已启用 | 初始化图；底板有效页面随后可接管 |
| 只有后台周期供电和 CMD03 读数 | 不因上电或读数自动亮屏 |
| 没启用 RST 且未收到底板显示命令 | 暗屏；S2 不退回普通按键扫描 |

底板诊断 HEX 的静态反编译显示：启动入口调用 rank5 发送函数，主循环随后发送 rank1；后台周期读数仅发送 CMD03。屏幕端复用现有 rank5，不添加新协议或修改底板固件。此结论不是本轮实测串口波形。

K1/K3 在主页切换主页编号，K2 进入菜单，这些单键路径不发送 rank5。屏幕端在原有页面活动策略判定从超时暗屏恢复后补发初始化图。软关机提示8/9之后，清提示不直接展示旧页面，等待新的有效页面再交接。若屏幕 MCU 一直有电且底板单键唤醒只重发完全相同的主页，协议无法将它与自动同页刷新区分，此边界需要底板提供明确唤醒命令，不能靠任意同页帧点亮。

## 启动图与主页交接

- 收到校验通过的 rank5 后，请求一次初始化图，不用 rank5 覆盖缓存页面字段。按照旧 Git 版本保留现有提示，常驻关机/开机提示由底板 msg0 显式清除；提示清除后再交接初始化图与页面。
- 收帧路径只置标志；显示任务在画启动图之前完成一次控制器初始化。约 255 ms 的原控制器等待仍存在，不再放到主页显示之后的一秒任务中执行。
- intro_pending 保留首图发送请求。主页即使同一 UART 批次紧跟着到达，也先缓存，不能吞掉首图。
- 完整图像发送后才开屏，再由随后显示事件接管最新页面。没有新增固定 1～2 秒停留；首图肉眼可见时长与面板扫描、串口及显示调度有关，实板待验。
- 测试图可以独立保持；新提示仍优先显示，结束后恢复适当目标。msg0 在没有目标时保持暗屏。
- CMD03 不创建显示目标、不请求重画、不修改页面状态；BLE 和采集后端继续运行。

## 烧录与检查

本次 HEX：`delivery/CH584M_TFT_HB_2.9寸_恢复旧版开机提示.hex`。此前分享包不包含本轮提示修正。

使用 USB 或串口 ISP 下载。在 WCHISPTool 选择实际 CH584 芯片，在下载配置勾选“使能RST作为手工复位输入引脚”，其他设置保持原生产设置，完成后断电重上电。硬件 RST 与单/双线调试条件有关，本版不在启动时自动修改任何芯片选项。

屏幕板 S2 固定接 PB23/RST#。按键会真正重启 MCU，临时中断蓝牙与串口。程序读取 `R8_GLOB_CFG_INFO` 中的 RST 状态及 `SYS_GetLastResetSta()`，仅 RST 启用且原因为 MR 时产生本地首图请求。外部复位也可能来自引脚干扰，不能据此保证一定有人按键。

UART1 115200 的新增日志：普通上电预期 `[RESET] enabled=1 cause=0x01`；S2 复位预期 `cause=0x03`。底板启动的 rank5 显示请求不要求 CH584 自身再次复位。
