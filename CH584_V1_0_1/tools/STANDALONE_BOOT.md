# 屏幕子 MCU 独立供电启动显示

2026-10-14：在本目录实现。沿用现有初始化图，不新增页面、不伪造底板 UART 帧。

## 原因与修改

底层 ST7305 驱动在 MCU 首次初始化时已经发送 8064 字节启动图并开屏。原 APP 的 u8g2Init 随即关屏，usart_task 再次强制关屏，screen_power 在从未收到显示帧时也判为关闭，因此没有底板指令时无法保持可见。

- APP/yuying_TFT.c：首次初始化后保持开屏；只清软件缓冲，不发送空白帧。运行中重新初始化仍沿用原调用方显式唤醒流程。
- APP/Usart3_task.c：任务启动根据屏幕策略同步实际开关和 Rx_sleep_flag，不再强制关闭。
- APP/include/screen_power.h：没有接收过有效显示帧时保持启动图可见；普通有效页面接管后，继续按原来的 time_light、导航变化和三级页面规则控制息屏。

串口协议、蓝牙和 Flash 代码、本轮之前的绘图加速、启动图资源和屏幕底层驱动未修改。

行为取舍：任何真正的 MCU 掉电重启都显示启动图，包括底板给子 MCU 周期上电且只读数据的情况。没有有效显示帧时启动图持续可见，不应用尚未接收的底板息屏设置。固件没有输入可用于区分独立供电与底板供电。

## 验证

- WCH 工具链全量重编，正式及诊断镜像生成成功；固件编译日志 0 error、0 warning。
- tools/verify_standalone_boot.py 从当前生产源码提取初始化函数、串口任务启动、显示事件及延后重初始化分支，编译实际 screen_power、ui_redraw_policy、ST7305 驱动和 CAD 发送封装。硬件 SPI、TMOS 调度及正常页面绘制使用记录桩。
- 模拟无底板显示帧运行一小时，启动图保持开屏，无空白重画；有效页面接管、超时关闭、相同页面不续亮、导航唤醒、三级常亮、退出三级后计时、运行中重初始化不重复写图及时间回绕均通过。
- 两个独立测试进程均通过，模拟清零 BSS 后再次启动。主机进程重启不等于实物掉电实验。
- 主机编译有原 u8g2 注释编码及类型转换警告；这些与 MCU 固件的编译诊断分开记录。

本轮备份、差异、测试及结果在 obj/standalone_boot_check；固件构建日志在 obj/ui_latency_check。baseline.hex 仍只是旧 UART/TFT 快照结合其他当前输入构建的对照镜像，不是本轮修改前完整固件，不用于本轮启动验收。

## 烧录及实板检查

推荐 obj/standalone_boot_check/standalone_boot.hex，内容与本轮 obj/CH584M_TFT_HB.hex 一致。自己用本目录工程全部重新编译后，烧录 obj/CH584M_TFT_HB.hex 也可以。obj/ui_latency_check/optimized.hex 与 diagnostic.hex 同时已更新，后者带耗时日志。

本轮未操作串口或烧录，实板行为尚未验证。最短检查：

1. 按模块正常供电要求，给屏幕子 MCU 和屏幕供电，先不接底板通信；检查初始化图自动出现并保持至少一分钟。
2. 完全断电后再次上电，检查仍能出现；实际显示需完成现有 MCU 和控制器初始化，不是零延迟。
3. 接回底板，检查主页及菜单正常替换启动图、超时息屏及按键唤醒正常。
4. 如有运行中屏幕重初始化操作，检查没有再次播放启动图。
